# Clink AI 开发工作流

本工作流根据 `docs/reference/CODEX-AGENTS.pdf` 提炼，并结合 Clink AI 当前代码结构、Ant Design v6 约束和本地预览方式落地。根目录 `AGENTS.md` 是自动执行入口，本文件提供操作细节。

## 一、任务入口

1. 明确目标、可观察完成标准和本次不处理的范围。
2. 检查 `AGENTS.md`、`docs/ARCHITECTURE.md`、Git 状态及任务对应代码。
3. 判断任务等级：
   - 简单明确：局部样式、文案、单一交互，直接执行。
   - 中等范围：多文件联动但方案明确，先发送简短实施计划后执行。
   - 高风险：架构选型、数据迁移、权限、删除、提交、部署或外部副作用，先确认关键决策。
4. 选择匹配的 Skill 或工具；没有匹配能力时使用通用工程流程，不强行扩大范围。

## 二、定位与修改

1. 运行 `npm run health` 了解当前层级、热点与变更影响。
2. 依据 `scripts/project-map.js` 和架构文档进入最小代码范围。
3. 先确认导入、导出、组件属性、API 路由和数据结构真实存在。
4. 优先沿用现有模式；只有在降低真实复杂度或重复时新增抽象。
5. 对超过 1200 行的文件，只在任务触及相应领域时按稳定边界拆分，避免无关重构。

## 三、实现检查表

- 功能：主路径、空数据、加载、错误、断网、权限和超长内容。
- UI：Ant Design v6、居中弹窗、文本完整、无重叠、响应式尺寸稳定。
- 动效：无突跳、无布局抖动、低开销属性、支持减少动态效果。
- 数据：发版不覆盖正式数据，删除有确认，测试数据完成后清理。
- 安全：前端不保存服务端密钥，不在输出或日志中暴露凭据。

## 四、验证矩阵

| 变更类型 | 最低验证 |
| --- | --- |
| 文档或规则 | `npm run health`，检查链接与路径 |
| `scripts/*.js` | `node --check <文件>`、`npm run check:changed` |
| Ant Design 工作台 | `npm run check:changed`、目标 DOM/交互检查 |
| 单文件页面 | `npm run build:standalone`、内联脚本检查、刷新现有预览 |
| 预览服务/API | 语法检查、`/api/health`、目标接口请求 |
| 发版 | `npm run check`、`npm run health`、浏览器目标流程、变更清单 |

## 五、交付与复盘

1. 更新 `updatelog.md`，记录时间、文件、行为和验证结果。
2. 删除测试产物与临时服务。
3. 刷新现有预览页，不创建重复标签页。
4. 最终说明完成状态、核心改动、验证证据、预览地址和剩余风险。
5. 若同类返工再次出现，优先增加可自动执行的检查；稳定重复流程再考虑封装为 Skill。

## 六、明确禁止

- 未读取现有代码就凭印象修改。
- 未运行验证就声称功能完成。
- 为了“整理”回滚用户改动或大范围格式化无关文件。
- 直接在生成产物或第三方源码中长期维护业务逻辑。
- 未经授权提交、推送、部署、删除正式数据或改变访问权限。
- 把密钥、密码、Token 或个人运行数据提交到仓库。
